> ● Ensure your development environment is fully set up with: ○ Node.js
> (Latest LTS)
>
> ○ Git
>
> ○ GitHub Account ○ TypeScript
>
> ○ NitroStack TypeScript SDK ○ npm or pnpm
>
> ○ Visual Studio Code (Recommended) ● Verify that you can:
>
> ○ Clone a GitHub repository ○ Install dependencies
>
> ○ Run a TypeScript project
>
> ○ Build an MCP Server locally using NitroStack ○ Push code to GitHub
>
> ○ Access Discord on your system throughout the hackathon.

💡 **Idea** **Selection**

> ● Be clear and confident about the idea you choose before you begin
> development. ● Put the ideas in markdowns before beginning.
>
> ● Ensure your project idea aligns with one of the **six** **official**
> **hackathon** **tracks**.
>
> ● Validate your idea with your teammates early so you can maximize
> your development time.

💻 **Development**

> ● Build your entire project using the **official** **NitroStack**
> **TypeScript** **SDK**. ● Ensure your solution aligns with one of the
> official hackathon tracks.
>
> ● Use NitroStack throughout the complete development lifecycle—from
> development and testing to deployment and final submission.
>
> ● Build your MVP (Minimum Viable Product) first, then continue
> improving it with additional features.
>
> ● Keep your code modular, clean, and easy to understand.

☁ **Deployment**

> ● Deploy your project to **NitroStack** **Cloud** as soon as you have
> a working prototype. ● Continue pushing updates to GitHub so
> NitroStack Cloud can automatically redeploy
>
> your latest changes.
>
> ● Test every deployment to catch issues early instead of waiting until
> the final submission. ● Validate your deployed application after every
> major milestone.

📂 **GitHub** **Best** **Practices**

> ● Commit your code frequently with meaningful commit messages. ● Push
> your latest changes regularly.
>
> ● Keep your default branch stable and deployable. ● Include a
> well-written README explaining:
>
> ○ Project overview ○ Installation steps
>
> ○ Environment setup ○ Architecture
>
> ○ Usage instructions
>
> ● Organize your repository so judges can easily understand your
> project. ● Use a proper .gitignore file and not delete the file or its
> content.

🤖 **AI** **Usage**

> ● Use the provided **5** **Million** **AI** **Tokens** responsibly. ●
> Use AI for:
>
> ○ Debugging ○ Refactoring
>
> ○ Prompt optimization ○ Testing
>
> ● Make sure you understand every piece of code you include in your
> project.

🧪 **Testing**

> ● Test your MCP Server regularly. ● Verify that:
>
> ○ MCP resources work correctly. ○ NitroStack Studio work correctly ○
> Tools execute successfully.
>
> ○ Dependencies install correctly. ○ Deployment succeeds.
>
> ○ Your application works end-to-end.
>
> ● Fix bugs as you go instead of saving everything for the last few
> hours.

🤝 **Getting** **Help**

> ● Read the provided resources before asking for help. ● Discuss with
> your teammates first.
>
> ● If you're still blocked, ask your question to the assigned
> volunteers.

📤 **Before** **Submission**

> ● Ensure your project is successfully deployed on NitroStack Cloud.
>
> ● Push the latest version of your code to GitHub.
>
> ● Submit your project to the official Sample Apps repository on GitHub
> ● Verify that your repository is complete and accessible.
>
> ● Follow the demo video reference/guidelines provided in the
> submission portal and record a demo video (maximum 3 minutes)
> explaining:
>
> ○ The problem statement ○ Your solution
>
> ○ A working demonstration of your project
>
> ● Submit your project through the official NitroStack Cloud Dashboard
> using the organizer-provided account.

📱 **Social** **Media**

> ● Coordinate with the NitroStack social media team whenever they
> approach your team for photos, videos, interviews, or demos.
>
> ● Be prepared to briefly explain your project, the problem you're
> solving, and what makes it unique.
>
> ● Help us capture your building journey and showcase your work to the
> wider developer community.

❌ **DON'Ts**

🚫 **Technology**

> ● Don't use any SDK other than the **official** **NitroStack**
> **TypeScript** **SDK**.
>
> ● Don't build your project using unsupported frameworks or SDKs if you
> expect deployment on NitroStack Cloud.
>
> 🚫**Idea** **Selection**
>
> ● Don't spend several hours trying to come up with the "perfect" idea.

🚫 **Deployment**

> ● Don't wait until the last hour to deploy your application.
>
> ● Don't assume your project will work in production without testing. ●
> Don't submit a project that hasn't been deployed successfully.

🚫 **GitHub** **&** **Security**

> ● Never upload:
>
> ○ API Keys
>
> ○ Access Tokens ○ Passwords
>
> ○ Credentials ○ .env files
>
> ● Never commit node_modules or secrets into github. ● Don't upload
> unnecessary large files or binaries.
>
> ● Don't make your repository private before judging is complete. ●
> Don't leave broken or incomplete code in your main branch.

🚫 **AI** **Usage**

> ● Don't ask AI to generate your complete project.
>
> ● Don't rely entirely on AI-generated code without understanding it. ●
> Don't blindly copy and paste code from AI.

🚫 **Development**

> ● Don't start coding before understanding the problem statement.
>
> ● Don't spend most of your time polishing the UI while ignoring core
> functionality. ● Don't skip testing.
>
> ● Don't ignore deployment until the end.
>
> ● Don't forget to push your latest changes to GitHub.

🚫 **Communication**

> ● Don't spam mentors or repeatedly tag multiple volunteers.
>
> ● Don't send direct messages to mentors unless they specifically ask
> you to.
>
> ● Don't ask questions without first checking the documentation or
> Discord discussions.

🚫 **Social** **Media**

> ● Don't refuse when the social media team approaches you for content.
>
> ● Don't hesitate to explain your project, it's an opportunity to
> showcase your work.

🚫 **Submission**

> ● Don't submit incomplete documentation.
>
> ● Don't forget your README or installation instructions. ● Don't leave
> environment variables undocumented.
>
> ● Don't submit a project that hasn't been tested. ● Don't forget to
> upload your demo video.
>
> ● Don't submit through any account other than the one provisioned by
> the organizers.
